# Security Risk Register

**Project:** `nadjimlab/wil`  
**Assessment date:** 2026-09-09  
**Assessment scope:** Repository code, SQL files, CI configuration, Vercel configuration, and package audit.  
**Production status:** No production connection, migration, policy change, or deployment was performed.

## Executive conclusion

The repository builds successfully, but it is not ready for public production release. The principal risks are an authorization model that can be bypassed by browser-local state, plaintext duplication of citizen identifiers, broad client-side complaint reads, incomplete migration discipline, and unverified production state. The remediation order is **P0 data and authorization boundaries, P1 workflow and operational controls, P2 resilience and performance, and P3 enhancements**.

## Sensitive-data classification

| Data | Current treatment | Assessment |
|---|---|---|
| Phone | Hashed in `phone_encrypted` by trigger `schema.sql:175-198`, but also stored in plaintext `citizen_phone` | The `*_encrypted` name is inaccurate: the reviewed trigger creates a SHA-256 digest, not reversible encryption. Plaintext duplication is P0. |
| National ID | Hashed in `national_id_encrypted`, but also stored in plaintext `citizen_nin` | The field is hashed, not encrypted. Plaintext duplication is P0. |
| PIN | Bcrypt-hashed by trigger when the value is not already bcrypt; realtime mapping exposes `row.pin_hash` | Never include PIN or hash in realtime/client payloads. |
| Complaint description | Returned by public `track_complaint` | Review whether full text is necessary for unauthenticated tracking; apply minimum disclosure. |
| Attachments | Stored in JSON/Data URLs in complaint objects; storage policy absent from repository | Treat as sensitive documents and move to private storage with signed URLs. |
| Internal notes | Broad active-staff `FOR ALL` policy in `schema.sql:223-228` | Scope by complaint and role; separate operations. |

## Release gate

No public production release should proceed until SEC-001 through SEC-007 have verified fixes, a deployed-schema inventory confirms the actual policies, and the role/RLS test matrix passes. This register is a plan artifact; it does not authorize execution.
